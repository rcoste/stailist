## Accepted Scope (added to this plan)

- Arquitectura "Base lista para v2": modelo de datos rico (Item/User/Outfit/Vote con atributos que anticipan gap-solver), catálogo canónico de prendas básicas como tabla semilla, instrumentación automática de TTV / ratio de votos / tiempos de generación, generación con estado de progreso en tiempo real.
- E1: pantalla de regreso = "tu look de hoy". **Se genera on-open** (al abrir la app) con el estado de progreso estándar (<30s), usando el último objetivo declarado + clima del día — NO generación en background ni cron (evita costo de API por usuarios que no abren la app). **Una generación por día**: re-aperturas el mismo día muestran el look ya generado (control de costos). Edge case: usuaria que regresa sin completar onboarding → retoma onboarding, no look del día.
- E4: manifest PWA + modo standalone ("agregar a pantalla de inicio"). Ícono placeholder neutro hasta el milestone de diseño. En iOS no existe prompt de instalación — incluir mini-instrucción in-app ("compartir → agregar a pantalla de inicio").
- E5: botón "me lo puse" disponible en **cualquier outfit del historial** (el historial persiste todo lo generado — regla #7 del alfa). Cuenta como métrica de señal de oro y alimenta la **regla de variedad**: el motor recibe como contexto los outfits usados/votados de los últimos 14 días y evita repetir combinaciones exactas recientes (es contexto de prompt, no un sistema aparte).
- E6: API de clima gratuita inyectada al contexto del prompt. **Ubicación**: geolocalización del navegador (un solo diálogo de permiso nativo, sin paso de UI propio en el onboarding); si la usuaria niega el permiso o la API de clima falla → el motor genera sin contexto de clima, nunca bloquea. Cero pasos agregados al onboarding.

## Requisitos adoptados en la review de 11 secciones (2026-06-10)

- **Acceso**: beta cerrada — allowlist de correos + magic link (Supabase Auth). Allowlist validada en servidor. Idioma: solo español.
- **Mapa de errores**: patrón uniforme retry 1x → mensaje amable, nunca pantalla muerta. Cubre: análisis de prenda (timeout/alucinación/vacío → confirmación editable o captura manual), generación (JSON malformado/refusal/timeout → retry → "el stylist está ocupado"), subida de fotos (retry + progreso), clima (degrada sin clima, transparente), magic link (botón reenviar), persistencia (retry + aviso no bloqueante).
- **Onboarding persistente por paso**: cada paso completado se guarda; interrupción en paso N retoma en paso N, nunca rehace pasos previos.
- **Seguridad**: (1) bucket de Storage privado con URLs firmadas, (2) RLS de aislamiento por usuario en todas las tablas, (3) allowlist server-side.
- **Tests — mínimo real**: fixtures del motor (JSON válido + solo prendas existentes — la falla #1 del alfa era inventar prendas), 1 E2E del onboarding completo, tests del armado de contexto de prompt (paleta/near-face/variedad), tests de instrumentación de eventos.
- **Performance**: compresión de imágenes client-side antes de subir (fotos de teléfono 5-10MB).
- **Prompt versionado**: cada outfit guarda la versión del prompt que lo generó (medir si los cambios de prompt mejoran el ratio de 👍).
- **Generación compatible con límites de Vercel**: streaming/respuesta progresiva (detalle en eng review).
- **Smoke test post-deploy**: generar 1 outfit real en producción.
